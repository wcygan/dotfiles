Exploration and planning

Three code approaches

A comparison artifact for choosing between implementation strategies before code is written.

  • Primary intent: explore
  • Interaction: static
  • Output: recommendation

Use when

The user asks for options, tradeoffs, or ways to implement the same behavior and has not committed to an approach.

Input signals

  • "Compare approaches", "which implementation", "tradeoffs", "alternatives".
  • Feature request with several plausible technical paths.
  • Enough repo context to show realistic snippets.

Borrow

  • Option cards with code, pros, cons, local fit, and risk.
  • Direct comparison using the same criteria for every approach.
  • A final recommendation that names the deciding tradeoff.

Avoid

  • Using this after the user has already chosen the approach.
  • Inventing snippets that are not grounded in the repo.
  • Presenting five or more choices unless the user asks for breadth.

Pair with

Use `04-code-understanding.html` to explain the existing flow first, or `16-implementation-plan.html` after the direction is chosen.

Validation

  • Every code snippet maps to real APIs or files.
  • Pros and cons are symmetric across options.
  • The recommendation is actionable.
