Exploration and planning

Visual design directions

A visual comparison artifact for reacting to different UI directions, tones, densities, and themes.

  • Primary intent: explore/design
  • Interaction: simple controls
  • Output: chosen direction

Use when

The user wants multiple visual approaches rendered side by side before deciding what style to pursue.

Input signals

  • "Generate directions", "mockups", "tone", "palette", "empty state", "compare designs".
  • Existing component or screen with unclear visual treatment.
  • Need for light/dark, density, or state comparison.

Borrow

  • Common frame for every variant.
  • Distinct labels and tradeoff notes per direction.
  • Theme or surface toggle when contrast matters.

Avoid

  • Using it as a full design-system reference.
  • Changing too many variables at once without naming the tradeoff.
  • Marketing-style hero treatment for utilitarian product UI.

Pair with

Use `05-design-system.html` for token grounding, `06-component-variants.html` for component states, or `08-prototype-interaction.html` when the flow needs to be felt.

Validation

  • Variants are visibly distinct and comparable.
  • Controls work in a browser.
  • Text fits on desktop and mobile.
