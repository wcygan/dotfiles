Annotated PR review

A review artifact for finding risk, annotating diffs, and guiding reviewer attention.

  • Primary intent: review
  • Interaction: collapsible files
  • Output: findings

Use when

The user asks for a PR/code review, wants risk triage, or needs a readable diff with inline commentary.

Input signals

  • PR number, diff, branch, patch, changed files, or "review this".
  • Concern about regressions, missing tests, or behavioral risk.
  • Need to explain severity and next actions.

Borrow

  • PR summary and risk map.
  • Rendered diff snippets with margin annotations.
  • Severity labels, collapsible low-risk files, and checklist.

Avoid

  • Using it when the user wants author-facing PR marketing rather than critique.
  • Commenting on style without behavioral risk.
  • Showing huge unannotated diffs.

Pair with

Use `17-pr-writeup.html` for reviewer-facing author notes, or `04-code-understanding.html` to explain unfamiliar subsystem context.

Validation

  • Findings cite concrete files or diff lines.
  • Severity labels are justified.
  • Recommended fixes and missing tests are explicit.
