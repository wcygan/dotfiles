Code understanding module map

A source-backed architecture note for explaining how a feature or subsystem flows through code.

  • Primary intent: explain code
  • Interaction: collapsible snippets
  • Output: mental model

Use when

The user asks how code works, where responsibilities live, or how requests/data move through a codebase.

Input signals

  • "How does this work?", "module map", "request path", "architecture".
  • Source files, package boundaries, middleware, providers, routes, services.
  • Need for a trust boundary or ownership boundary explanation.

Borrow

  • One-paragraph mental model first.
  • SVG flow map and ordered callstack walkthrough.
  • Source snippets in details blocks with file paths.

Avoid

  • Teaching a general concept without repo-specific source.
  • Listing files without showing the flow between them.
  • Omitting the boundary where behavior becomes risky.

Pair with

Use `14-research-feature-explainer.html` for a more tutorial-like feature summary, or `13-flowchart-diagram.html` for interactive operational paths.

Validation

  • Every file path exists.
  • The flow order matches actual calls or data movement.
  • Snippets are short and directly relevant.
