Design system reference

A portable style reference generated from tokens, components, and existing UI conventions.

  • Primary intent: design system
  • Interaction: optional copy
  • Output: style guide

Use when

The user needs agents or collaborators to match the product's visual system in future artifacts or implementation.

Input signals

  • "Design system", "tokens", "brand reference", "style guide".
  • CSS variables, token files, component libraries, screenshots.
  • Need to make future HTML artifacts match local taste.

Borrow

  • Color swatches by role, typography scale, spacing, radii, shadows.
  • Rendered controls and common components.
  • Copyable token names and source provenance.

Avoid

  • Using it to compare just one component's prop variants.
  • Inventing a new palette instead of reading tokens.
  • Making a marketing brand page.

Pair with

Use `06-component-variants.html` for a single component matrix or `02-exploration-visual-designs.html` for direction exploration.

Validation

  • Token values match source files.
  • Examples render with the documented tokens.
  • Contrast and mobile layout are readable.
