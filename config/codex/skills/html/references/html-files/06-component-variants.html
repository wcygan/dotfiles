Design

Component variant matrix

A focused review surface for one component across props, states, sizes, themes, and density settings.

  • Primary intent: component review
  • Interaction: controls
  • Output: variant decision

Use when

The user wants to inspect, tune, or document a specific component and its variants.

Input signals

  • "Component variants", "all states", "prop matrix", "button/card/input states".
  • Existing component API or design tokens.
  • Need to compare hover, disabled, selected, density, size, or theme states.

Borrow

  • Control bar for adjustable props.
  • Grid of repeated live variants.
  • Best-for notes and prop combo labels.

Avoid

  • Broad screen-level design exploration.
  • Rendering variants that cannot exist in the real component API.
  • Controls that resize or shift the whole layout awkwardly.

Pair with

Use `05-design-system.html` for token context or `07-prototype-animation.html` for interaction state timing.

Validation

  • Controls update every applicable variant.
  • All important states are visible.
  • Grid holds on mobile without text overlap.
