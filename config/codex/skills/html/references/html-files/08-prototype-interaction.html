Prototype

Clickable interaction prototype

A throwaway prototype for testing workflow, gesture, drag, or click behavior before implementation.

  • Primary intent: interaction prototype
  • Interaction: direct manipulation
  • Output: design decisions

Use when

The user needs to feel an interaction and push back on ergonomics before it is built in the app.

Input signals

  • "Clickable flow", "drag to reorder", "prototype this interaction", "feel".
  • A workflow with uncertain affordances or gesture rules.
  • Need to document design decisions and open questions.

Borrow

  • Minimal native interaction without framework setup.
  • Large demo area plus side panel explaining what to notice.
  • Open questions and intentionally omitted polish.

Avoid

  • Using it for final production-ready implementation.
  • Hiding known limitations.
  • Forgetting keyboard or fallback considerations when relevant.

Pair with

Use `07-prototype-animation.html` for timing details, or `18-editor-triage-board.html` when the interaction manipulates real sortable data.

Validation

  • Core interaction works in browser.
  • Prototype explains decisions and omissions.
  • Mobile/touch behavior is either tested or explicitly out of scope.
