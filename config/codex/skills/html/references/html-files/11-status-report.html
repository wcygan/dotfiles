Reports

Weekly status report

A skim-friendly update artifact for shipped work, metrics, risks, and next steps over a known time window.

  • Primary intent: report
  • Interaction: static
  • Output: stakeholder summary

Use when

The user wants a routine team, engineering, project, or leadership update that should be read quickly.

Input signals

  • "Weekly status", "what shipped", "status report", "leadership update".
  • PRs, issues, deploys, incidents, metrics, or dates.
  • Need to separate highlights from details.

Borrow

  • Metric band with deltas and time window.
  • Highlights, shipped table, in-progress section, risks/blockers.
  • Small chart only when it improves scanning.

Avoid

  • Postmortem structure for a normal status update.
  • Unlabeled metrics or missing date ranges.
  • Deep implementation details that belong in a plan.

Pair with

Use `09-slide-deck.html` when presenting the status live, or `12-incident-report.html` for a failure-specific section.

Validation

  • Date range and sources are visible.
  • Metrics have units or definitions.
  • Risks and next steps are actionable.
