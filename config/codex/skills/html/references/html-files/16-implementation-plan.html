Exploration and planning

Implementation plan

A handoff artifact for turning an agreed direction into slices, risks, tests, rollout, and rollback.

  • Primary intent: plan
  • Interaction: mostly static
  • Output: implementation handoff

Use when

The user wants a thorough plan that another agent or engineer can execute from a fresh session.

Input signals

  • "Implementation plan", "handoff", "milestones", "risk table", "rollout".
  • Feature scope, affected packages, data model, tests, deployment concerns.
  • Need for code snippets and sequence of work.

Borrow

  • Summary facts, milestones, mockups, data-flow SVG.
  • Key code snippets, risk table, rollout, rollback, test plan.
  • Slices that are independently reviewable.

Avoid

  • Using it before key options are compared.
  • Writing vague phases without acceptance checks.
  • Omitting rollback or migration notes for risky changes.

Pair with

Use `01-exploration-code-approaches.html` before choosing direction or `17-pr-writeup.html` after implementation.

Validation

  • Every milestone has concrete deliverables.
  • Risks, tests, rollout, and rollback are explicit.
  • Plan references actual files and repo patterns.
