Code review

PR writeup for reviewers

An author-facing PR artifact that explains motivation, behavior change, reading order, and review focus.

  • Primary intent: explain PR
  • Interaction: collapsible files
  • Output: reviewer guide

Use when

The user wants to attach a helpful explanation to a PR so reviewers can understand the change quickly.

Input signals

  • "Write up this PR", "reviewer guide", "explain motivation", "file-by-file".
  • Diff, PR metadata, changed files, before/after behavior.
  • Need to direct reviewer attention.

Borrow

  • TL;DR, why, before/after behavior.
  • File-by-file reading order, not alphabetical order.
  • Focus areas, rollout notes, hidden secondary file details.

Avoid

  • Critical bug-hunting tone when the user asked for author guidance.
  • Repeating the diff without explaining why.
  • Ignoring reviewer context or unfamiliar code areas.

Pair with

Use `03-code-review-pr.html` when the task is critique, or `11-status-report.html` when the PR is part of a broader update.

Validation

  • File list matches actual changes.
  • Before/after claims are evidence-backed.
  • Review focus areas are specific.
